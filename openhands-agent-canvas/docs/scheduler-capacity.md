# 推理与保存分别限流（5.21 / 插件 2.20）

独立节点不会因同一运行的另一个节点已完成模型、正在保存输入/输出快照而占用推理名额。maxParallelNodes 仍由负责人决定，范围 1–5；它限制该运行的准备和推理任务。输出未通过 SHA-256 与数据桶屏障时，真正依赖该节点的下游仍然等待。

全局最多 5 个准备/推理节点。DAG 运行另有最多 10 个常驻调度循环、最多 10 个未结束阶段工作；保存慢时会对新阶段施加背压，避免积累无界的上传、归档与连接。历史串行运行仍最多 3 个，且与 DAG 共享全局 5 个执行名额。上述为控制器限额，不是服务商容量或五个账号各自的并发承诺。

查询恢复候选时，所有 running/reconnecting/stopping 记录都会被读取；排队候选分别取最早 20 个 DAG 与 20 个历史串行运行，再按时间排列。大量历史串行排队不会遮住 DAG，旧排队记录也不能隐藏已提交的原生会话。重启先保留已有推理名额，未确认停止前不能视为取消。activeNodeIds 包含仍在保存的阶段，不是正在推理的模型数。

模型、深度、分工与真实依赖由负责人按需求决定，DeepSeek 继续 V4.1 Flash/max。存储失败保留已完成推理，继续时只补存储。新调度不提前解锁依赖、不取消桶屏障，也不重跑已完成模型。

验证：HTTP 原生文件与签名 S3 夹具覆盖同一运行保存/推理重叠、五个独立运行占满全局、保存积压背压、取消、恢复和真实依赖；另有 SQLite 混合长队列与恢复保留名额检查。可选比较：CANVAS_SCHEDULER_BASELINE=/绝对路径/旧源码 CANVAS_SCHEDULER_REPORT=/tmp/report.json node scripts/test-parallel.mjs。其模型响应和存储延迟可控，不能据此声称真实 AI 项目整体提速 11 倍。
