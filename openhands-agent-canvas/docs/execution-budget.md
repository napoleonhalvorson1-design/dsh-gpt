# 执行预算与一次后备（5.13）

AI 负责人可为分工设置 `executionPolicy`。预算从请求提交开始计算，包含原生启动、生成及工具等待；它不同于 ACP 的空闲超时。适合给可能拖住整个任务的阶段设置等待上限，长任务应给足时间。没有策略的历史阶段继续原行为。

```json
{
  "executionPolicy": {
    "budgetSeconds": 300,
    "fallbackProfile": "codex-seoul",
    "fallbackModelPolicy": {"model": "gpt-6.1-sol", "effort": "medium"}
  }
}
```

只允许自托管入口，预算为 30–7200 整数秒。备用入口和模型必须来自已验证目录；自动模式下负责人决定备用模型与思考深度。用户手动指定优先，DeepSeek 始终 Flash/max。策略与备用配置随本次运行冻结，不随全局配置升级变化。可只写预算而不设置备用入口，超时后确认停止并保留现场，等待明确继续。

新的 `adaptive + strongest` 规划阶段默认预算 300 秒，备用只选相同已验证模型、相同深度的另一个入口，不降低规划能力。至少三个匹配入口、模型、深度、规划角色与难度的成功观测存在时，取中位耗时三倍，限制在 300–900 秒。直接实现的观测不用于估计规划耗时。没有相同能力入口时仅设置预算；显式节点策略优先。其他开发阶段仍由负责人按需求设置。

到期先持久化停止状态，再等待原生服务两次确认停止。网络错误、进程重启、停止请求本身均不视为停止成功。若原会话恰好完成且有有效输出，优先保存原成果。用户请求取消后不启动备用。原始输入必须完整入桶才切换，存储失败只恢复存储。

最多自动切换一次。配置、新请求 ID 和备用工作目录在一个事务中保存，重启恢复同一请求；备用使用相同的上游快照，在新隔离目录开始，不混入原会话未完成文件。原目录、请求 ID、模型及停止时刻保留在 `node.attempts`。备用仍超时则确认停止并报告失败；用户明确继续可恢复当前暂停会话，不自动反复换模型。完成的 AI 遇到输出入桶失败，只重试文件保存。

`canvas runs performance --id ID` 保留原尝试的模型等待，计入模型累计量、并行墙钟与总任务时间；不会通过清零失败等待宣称提速。执行观测把已确认停止的尝试单列，不当作成功交付。严格的停止确认和桶屏障意味着预算是切换的触发时间，并不保证整个阶段在该秒数内结束。

验证用 `node scripts/test-execution-budget.mjs`：真实本地 HTTP、原生文件协议、签名 S3 夹具及 SQLite 重启，无真实模型调用。覆盖停止未确认、切换事务后重启、晚到成果、取消、一次上限、明确续跑、输入输出存储失败及冻结策略。整体快 11 倍仍需同需求真实任务证明。
