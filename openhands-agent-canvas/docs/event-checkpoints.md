# 模型事件与节点状态同批保存（5.22）

DAG 与历史串行执行器在读取一页原生事件后，用一个 SQLite IMMEDIATE 事务保存事件、对应输出、错误及读取位置，提交成功后才更新内存对象。网络请求先完成，事务内不等待网络。不再为每条事件单独提交两次，WAL 与 synchronous=FULL 保留。

这解决“事件日志已保存，节点输出或下一页位置尚未保存”之间的异常退出窗口。提交前退出，整页回滚，恢复后可重新读取原生事件；提交后退出，整页事件和输出都在。已有事件 ID 去重、输出长度上限、密钥隐藏及 provider 错误识别保留。DAG 仍读最新运行后只合并本节点，不能覆盖同时完成的兄弟节点或取消标记。

测试 scripts/test-event-checkpoint.mjs 使用原生事件 HTTP 夹具和实际文件 SQLite：事件插入后失败、COMMIT 前失败、分页重读、并发兄弟状态、取消、敏感信息隐藏及 fatal 事件；另起进程在插入后和 COMMIT 后直接退出，检查真实 WAL 恢复。可选 CANVAS_EVENT_BASELINE=/绝对路径/旧执行器目录 运行同一测试，比较一页 100 条事件的保存耗时。局部样本不代表真实模型或整项任务快 11 倍。

配套插件 2.20 继续兼容，不需要修改已有项目。此版本没有自动重发原生消息：已核实 SendMessageRequest 不带客户端幂等 ID，429 说明消息可能已保存。后续同会话修正必须先有持久化发送记录和结果核对，不能因网络超时直接重发。
