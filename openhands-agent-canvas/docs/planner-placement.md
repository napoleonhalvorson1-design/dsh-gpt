# 强规划入口的有界分散（5.16）

strongest 仍先选最强已验证模型。新运行提交时，在同一原生引擎、同模型、同思考深度的入口中，优先选择本工作台已保留推理任务较少的入口。负载相同保留原入口，减少不必要的冷启动。没有兼容入口则继续原路由，不降低模型或深度。manual 规划或手动模型模式不参与自动分散。

这是控制器的保留任务计数，不是服务器 CPU、服务商队列或账号限额。只数运行/重连中的节点，以及依赖已入桶、能够开始的排队节点；已经完成模型、仍在保存文件的阶段不再占推理保留量。取消中的未启动任务不数，原会话确认停止前仍保留实际执行节点。旧串行任务只数当前节点。工作台外部的任务不在此计数中。

候选入口必须保留原 focused/inherit 设置、已验证模型及深度，并满足显式备用策略；不会把主入口放到与备用完全相同的位置。自动规划预算取原入口与新入口估时的较大值，避免分散后因缺少历史而缩短已有预算。显式预算优先。最多五个模型节点和原有工作流上限保持不变。

选择与配置、请求 ID、独立目录一同保存。modelSelection.placement 给出 from/to、strategy 和当时保留量；它不表示模型已启动或被服务商确认，实际模型仍看 selectionApplied 及桶快照回执。既有请求、已经开始的会话、后续开发阶段和历史运行不重新分配；开发阶段的入口继续由负责人决定。

继续时使用原规划入口的当前凭据，保留该运行选定的模型、深度、上下文和不可变策略路径。入口不存在或地址已变化时拒绝继续，避免连接另一个后端。只读模型预览使用当前保留量，但不建立保留；真正提交前按最新情况选择。

执行分支的提示与配套技能现在区分工作台操作者和本地开发职责，避免已获隔离目录的分支再次走接入流程。App、外部工具和模型能力未删除；插件加载与实际 token 变化仍需原生任务观测，不能用说明文字变化宣称提速。

`node scripts/test-planner-placement.mjs` 使用持久 SQLite 和本地原生 HTTP 夹具，验证三请求分散、同模型同深度、实际请求地址/目录、重启、只读预览、备用约束及续跑冻结。不会调用真实模型。它证明路由行为，不证明真实项目整体快 11 倍，也不证明三个服务器使用不同账号。
