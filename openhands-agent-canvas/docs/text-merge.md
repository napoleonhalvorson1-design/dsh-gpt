# 同文件独立实现的自动汇合（5.28）

新的 DAG 运行在派发前固定 `textMergeVersion=1`。最强负责人仍自行选择人数、模型、深度、职责和依赖，可将已有模块中互不相交的函数分给不同 AI；不必因为文件名相同就再叫一个整合 AI。直接交付和独立文件交付仍可使用，不强制增加分工。

需要共同基线：可来自仓库、上轮成果或负责人完成的模块骨架。配合 5.27 时，负责人可提前冻结骨架及接口，让工作分支分别实现独立区域，自己完成其他文件；负责人不再改已冻结文件。全新且无公共文件的并发创建不会猜测如何拼接。

控制器从已确认的桶快照取回共同基线和各分支，以确切行字节计算每个分支相对基线的替换、删除和插入。完全相同的修改只应用一次；所有修改互不重叠才合并，不选赢家、不覆盖后一个分支。插入点落在其他修改的边界也保守视为冲突。结果保留 UTF-8、CRLF、末尾换行及执行位；父快照保持不变。

以下继续保留基线、每个分支及显式 resolutions.json：重叠修改、竞争插入、删除文件与修改文件竞争、二进制/无效 UTF-8、执行位变化、缺少共同文件、文件与目录冲突，以及超出处理上限。每版文件最多 256 KiB、4000 行，每次汇合共享 800 万行对工作预算，整体原有 128 MiB/5000 文件边界保持。超限回退原冲突流程，不用无界计算阻塞其他运行。合并结果沿用原有内存/磁盘暂存边界。

`node.mergeReport.autoMerged` 和多叶交付的 `run.finalMerge.autoMerged` 记录路径、算法版本、基线 SHA、各父版本 SHA 和结果 SHA，不含代码内容。报告及输入照常保存到桶，真实模型/深度回执、依赖与存储屏障继续生效。文本无冲突不证明接口或业务语义兼容，仍由负责实现的 AI 或指定最终命令做与改动相关的检查。

历史运行没有版本标记，继续逐文件显式解决。重启保留已固定的策略、原请求和成果；增量开发重建使用来源运行的版本，不因升级改变旧产物。存储失败只补存储，不重放模型。

验证包括真实 Python 归档、多分支 UTF-8/CRLF/删除/插入/执行位/资源边界、100 组生成的独立改动，以及隔离 HTTP/S3 的并行实现、重启和增量重建。固定模型夹具可以验证少一次整合调用，不能证明真实项目整体快 11 倍。升级验证没有调用付费模型。
