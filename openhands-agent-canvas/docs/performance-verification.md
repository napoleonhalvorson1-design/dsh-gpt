# 运行速度优化验收 · 2026-10-26

网站 5.2.1，原网站、Site、App、插件 2.2.0、密码、账号及七彩云配置保留。五 AI 的八个职责节点和验收依赖不变；本次未启动新的真实 AI 任务。

## 优化

1. 文件交接只解压一次，先检查全部路径和目标符号链接，再最多四路并发上传；不同工作流共享四个上传槽及 32 MiB 原文件缓冲预算。文件交接的解包/检查进程最多两个。失败时等待所有在途上传结束，清理专用临时目录，避免下游在后台写入未结束时启动。
2. 同一已校验 S3 快照的并发读取合并为一个下载。执行分支和阶段预览允许复用已从桶下载并验证的本地副本，每次仍核对大小与 SHA-256；最多记忆 64 个已验证副本。缓存损坏会重新下载；配置、凭据、桶或摘要变化不能误用旧缓存。默认显式 restoreCheckpoint 仍刷新桶，保留独立的远端完整性检查。
3. S3 SDK 客户端复用连接。原有 send/destroy 调用改为借用/释放连接，配置变化后旧连接在请求完成后回收；错误、取消和 HTTP 客户端提前断开都会释放下载。
4. 没有进度变化的节点轮询不再写 SQLite、递增 revision 或触发后续状态上传；真实输出与状态变化仍立即持久化，且保留停止请求和其他分支数据。
5. 登录后的静态 JS/CSS/图标/模板和下载资源支持内容 ETag 与 private/no-cache，未变化时返回 304。每次仍先验证登录，HTML、项目数据、运行及 API 响应继续 no-store。

## 可重复 HTTP 基准

执行 `CANVAS_PERF_BASELINE=/tmp/canvas-speed-baseline-5.2.0 CANVAS_PERF_REPORT=/tmp/canvas-speed-fixture.json node scripts/test-performance.mjs`。基线为优化前 5.2.0 源码副本；正常 npm test 不依赖这个临时副本。

同一 81 个小文件（含二进制，共 9835 字节），真实本地 HTTP 文件协议 fixture，每次上传固定 25ms 延迟。优化前交接 **6329ms**，优化后 **705ms**，本次减少 **89%**。这是文件交接基准，不是整个 AI 开发任务的加速比例。

八个同时读取者：桶 GET 从 **8 次 → 1 次**；随后八次已验证副本读取，GET 从 **8 次 → 0 次**。三次必须刷新桶的读取，从三个 TCP 连接改为一个连接。五十次无变化轮询，持久化写入从 **50 次 → 0 次**。

新增性能/安全回归共 **414 项检查**，覆盖全局并发/缓冲预算、大文件、原字节、恶意路径、目标符号链接、失败收尾、缓存和远端损坏、凭据/桶变化、HTTP 提前断开、连接释放以及登录后 304 与未登录拒绝访问。
