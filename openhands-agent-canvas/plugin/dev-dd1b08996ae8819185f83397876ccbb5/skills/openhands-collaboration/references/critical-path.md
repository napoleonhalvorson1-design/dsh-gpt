# 依赖路径优先调度（5.25）

新自主协作运行把 `schedulingVersion=1` 冻结在运行中。负责人仍决定人数、角色、模型、思考深度和依赖；调度只改变已经具备运行条件的节点抢占空闲槽位的先后。优先运行剩余依赖路径权重较大的阶段，减少短叶子占满槽位而延迟长链路的问题。同权重保持原顺序。

负责人可在阶段中填写 `estimatedSeconds`（1–7200 的整数），表示预计工作时间，不是超时预算，不触发额外模型调用。未提供时，使用同入口、已验证模型、深度、阶段类型和复杂度至少 3 个成功样本的中位模型耗时。不能匹配的阶段保留 `durationMs:null, source:"unknown"`；排序时共用本计划已知估计的中位权重，没有已知估计时共用单位权重。这个权重不声称测得未知任务的耗时。

估计和来源保存为 `run.scheduling`，与展开后的 DAG、节点配置同事务写入，续跑和重启不重估。已完成模型的自身权重归零；后继仍须等待文件 SHA-256 校验和对象存储屏障。排序不修改 `run.order`、依赖、模型、深度、预算、并发上限、成果或推理次数。既有运行和固定工作流保留原调度顺序。

`node scripts/test-critical-path.mjs` 覆盖模型/样本匹配、未知值、估计优先级、稳定排序、旧运行及真实 DAG 调度循环的并发与桶屏障；原生 HTTP/S3 协议测试另确认负责人估计确实随展开计划落库。相同七阶段、两个槽位的等时长受控任务由 500 降到 400 个时间单位（1.25 倍），仅证明该调度实例，不代表真实 AI 或整体 11 倍。启发式排序不保证任意任务最优。
