# 插件与网站配套升级

同一服务的稳定标识见包根目录 `compatibility.json`。不要创建第二个插件、网站或 App。

## 服务使用者

插件更新沿用当前插件 ID，现有账户绑定继续使用。新工具或技能尚未刷新时，重新打开该插件或新建一个选中此插件的 Codex 会话，不要重建插件。技能包升级不需要重新输入 S3 或模型密钥。

手机工作台的「设置 → 通过 Codex 操作」提供配套插件版本、插件入口和下载包。日常服务升级继续使用原网址。

## 获得源码修改权限的维护者

1. 在现有网站源码仓库工作，确认 `.openai/hosting.json` 的 project_id 与 `compatibility.json` 一致。读仓库 AGENTS.md，检查当前版本及活动运行，不覆盖服务器的环境文件和账号登录配置。
2. 网站/API 改动使用现有 Sites 源码与发布流程。服务器后台改动使用仓库的部署脚本；发布前完成对应测试。服务器升级检查活动任务，任务恢复不能重新调用已经完成的 AI。
3. 插件技能与模板源码位于 `plugin/dev-dd1b08996ae8819185f83397876ccbb5/`。修改说明后增加插件 SemVer；不改 App 生成的名称、展示信息、App/MCP 绑定与权限。
4. 运行 `npm run plugin:pack` 验证并生成更新 ZIP；`npm run build` 会将同一包和版本信息加入网站下载入口。打包工具检查模板入口、声明的工具契约、保留的 App 配置、完整文件列表与引用，并排除密钥和运行数据。
5. 账户更新使用 Plugin Creator 的 `get_plugin_files` 重新取得当前清单与 current_release_id。对比来源后，以原 plugin_id、当前 expected_release_id 和打包 ZIP 调用 `update_plugin`。如果版本已变，先读取新内容再合并，不能只替换 release ID 强行覆盖。上传后回读验证技能、App 绑定和新版本。
6. 发布现有 Site，刷新其 MCP 工具；Sites 生成的同名插件继续复用，App 刷新会保留符合条件的技能更新。之后再次读插件源，确认网站刷新未丢失技能。
7. 使用真实插件做一次只读 `canvas_list_projects` 和 `canvas_storage_status` 检查。不要为了升级验收启动新的五 AI 任务。工具尚未刷新时如实说明已保存版本和实际可用的工具范围。

插件包不携带服务器程序、数据库、运行产物、私钥或环境文件。网站/执行服务仍在原服务器运行；包里的 App 绑定与技能负责在聊天里调用这些服务。
