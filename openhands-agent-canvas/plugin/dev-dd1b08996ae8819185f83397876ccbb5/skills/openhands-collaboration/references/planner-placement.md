# 规划入口选择

strongest 先保持最强已验证模型，再在同原生引擎、同模型、同思考深度的入口中，选择本工作台已保留任务较少的入口。平局保留原入口，没有兼容入口则等待原入口；manual 规划或模型模式不自动分散。开发阶段仍由负责人决定。

依赖尚未入桶的任务不计保留，已完成模型、正在存储的任务释放推理保留量；取消未确认的实际执行仍保留。此计数不知道其他程序的任务、服务商队列和账号限额。全局推理上限仍为五个。

modelSelection.placement 记录 from/to、strategy 和选择时保留量；profileId、workspace 给出本次真实路由。它们仍不是模型确认，selectionApplied 及已校验快照才证明选择已生效。只读预览不派发任务、不建立保留；新运行提交时重新选择。

上下文、显式预算和备用限制保留，分散不会缩短原入口已学习的自动预算。既有请求、开始的会话和历史运行不改派。继续回到原规划入口，使用当前凭据和冻结策略路径；入口不存在或地址变更时先恢复同一入口，不切到另一个后端重跑成功成果。

执行分支只按本次隔离目录与职责开发本地文件，协作写 plan.json 交引擎派发；工作台管理需求才使用项目、接入与运行 API。新增规则保留外部工具能力，其实际 token 与延迟收益仍需真实任务观测。
