# 规划错误的定点修正（5.24 / 插件 2.21）

新建 strongest 自主协作运行冻结 planRepairVersion=1。已验证负责人的模型执行完成、阶段快照已校验入桶后，如果计划格式、依赖、模型选择或直接交付文件不符合要求，引擎最多自动修正一次。剩余原执行预算至少要有 30 秒；自动修正不延长原预算。不适用于存储故障、执行中的原生会话或旧运行，不另设审查 AI。

修正继续使用原负责人、模型、深度与冻结策略，在新的隔离目录中加载已校验成果，保留代码、二进制及执行位。原计划放在 .canvas-collaboration/rejected-plan.json，提示中说明具体错误；不复制旧运行回执或原生思考内容。使用新的原生会话和持久化请求 ID，完整任务继续提供。有效计划仍须通过原有文件、模型回执与桶屏障，才能启动开发分支。

修正请求先落库，再派发；重启复用同一请求 ID。原始与各次修正的输入、阶段归档和回执分别保存，repair-N 不覆盖原始快照。存储失败保留已完成推理，继续时只补存储。取消会阻止尚未派发的修正。自动修正再次失败则保留错误，等待明确继续；手动继续沿用最新已校验成果和本次错误，保留前几次尝试。

读取 runs status 的 nodes.plan.autoPlanRepairCount、planRepair、attempts。性能统计保留所有尝试和等待，已完成但无效的计划单列 invalidPlanSamples，不算成功，也不伪装成中断样本。本功能不声称整体已达 11 倍。

同时，创建会话的响应丢失且会话暂不可见时，继续操作保留原预留请求 ID，并先核对原生会话，避免换一个 ID 重复派发。已确认原生会话结束且需要重新执行时，才创建新请求。协议测试覆盖响应丢失、暂时 404、单次修正上限、代际快照、同模型/深度、剩余预算、取消、重启及存储重试；测试不调用真实模型。
